# Sticker-bot

[![Python](https://img.shields.io/badge/python-3.10+-blue.svg)](https://www.python.org/)
[![License: MIT](https://img.shields.io/badge/license-MIT-green.svg)](#лицензия)
[![Docker](https://img.shields.io/badge/docker-ready-2496ED.svg)](#запуск-в-docker)

Личный Telegram-бот на базе [Telethon](https://docs.telethon.dev/), работающий в режиме userbot — от имени вашего аккаунта. Позволяет пополнять собственный стикерсет одной командой, без ручной загрузки через официальных стикер-ботов.

Бот принимает изображение, GIF или стикер, конвертирует его в формат стикеров через `ffmpeg` и добавляет в указанный в конфигурации стикерсет. По желанию готовый стикер пересылается в заданный канал.

> ⚠️ Userbot реагирует только на сообщения, отправленные самим владельцем аккаунта (`from_users='me'`). Другие пользователи не могут управлять ботом.

## Возможности

- Добавление стикеров в стикерсет командой `!стик` (имя команды задаётся в `app.py`)
- Автоматическая конвертация изображений, GIF и анимированных стикеров через `ffmpeg`
- Опциональная пересылка добавленных стикеров в Telegram-канал
- Автоматическая очистка временных файлов при запуске и после обработки

## Требования

- Python 3.10+
- Telegram API-ключи ([my.telegram.org](https://my.telegram.org) → *API development tools*)
- `ffmpeg` в системе (для Docker — уже включён в образ)

## Установка

```bash
git clone https://github.com/ForeverAlkash/stick_bot.git
cd stick_bot

python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

pip install -r requirements.txt

cp .env.example .env
```

## Конфигурация

Заполните файл `.env` (создаётся из `.env.example`):

| Переменная | Обязательная | Описание |
|---|---|---|
| `API_ID` | да | ID API из [my.telegram.org](https://my.telegram.org) |
| `API_HASH` | да | Hash API оттуда же |
| `STICKERSET_NAME` | да | Короткое имя стикерсета (латиница, без пробелов) |
| `STICKERSET_TITLE` | да | Отображаемое название стикерсета |
| `CHANNEL_ID` | нет | ID канала для пересылки добавленных стикеров |

При первом запуске Telethon запросит номер телефона и код подтверждения и создаст файл сессии `session.session`. Повторная авторизация не требуется.

## Использование

1. Отправьте себе изображение, GIF или стикер (можно переслать из любого чата).
2. Ответьте на него командой `!стик` или отправьте команду следом.
3. Стикер будет сконвертирован и добавлен в стикерсет. Бот подтвердит добавление сообщением.

> Имя команды определено в `app.py` в обработчике `handle_sticker_command` — при необходимости измените регулярное выражение `pattern`.

## Запуск в Docker

```bash
docker build -t sticker-bot:latest .
docker run -d --name sticker-bot --restart unless-stopped sticker-bot:latest
docker logs -f sticker-bot
```

При первом запуске в контейнере потребуется интерактивная авторизация — удобнее создать сессию локально (`python app.py`) и собрать образ уже с готовым `session.session`.

Перенос готового образа на сервер:

```bash
docker save sticker-bot:latest | gzip > sticker-bot.tar.gz
# на сервере:
gunzip -c sticker-bot.tar.gz | docker load
docker run -d --name sticker-bot --restart unless-stopped sticker-bot:latest
```

> **Внимание:** образ содержит `.env` и `session.session` с личными данными. Не публикуйте его в публичных реестрах и передавайте только по доверенным каналам.

## Структура проекта

```
app.py                      # точка входа: клиент Telethon, обработчик команды
config/config_handlers.py   # логгер, очистка временных файлов, отложенное удаление сообщений
handlers/sticker_control.py # конвертация медиа и добавление стикеров в стикерсет
Dockerfile                  # сборка образа (python:3.11-slim + ffmpeg)
.env.example                # шаблон конфигурации
```

## Безопасность

- `.env` и `*.session` исключены из репозитория через `.gitignore` — секреты не попадают в git
- `API_HASH` и файлы сессии дают полный доступ к аккаунту — не публикуйте и не передавайте их
- Если секрет всё же попал в репозиторий: отзовите его (создайте новый `API_HASH` на my.telegram.org) и завершите сессию в Telegram (*Settings → Devices*). Историю коммитов в этом случае также нужно переписать или удалить репозиторий
